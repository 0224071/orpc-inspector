# 保留紀錄

[English](./preserve-log.md) | 繁體中文

整頁重新整理或換到另一個頁面後，面板仍保留之前的呼叫，就像瀏覽器 Network 分頁的 **Preserve log**。需要的呼叫剛好發生在換頁前時用它：登入後跳轉、送出表單後換頁、401 把你導到登入頁。

## 開啟

勾選面板工具列「清除」旁的「保留紀錄」。

- 預設關閉。
- 開啟時，清單中已有的呼叫也會保留。
- 設定只記在這個瀏覽器分頁。在同一個分頁重新整理或換頁都還在，新分頁預設關閉。
- 關閉時會立刻刪除保存的副本。清單中已有的呼叫會留到清除或重新整理為止。

頁面不能使用 `sessionStorage` 時（例如在 sandbox iframe 裡，或隱私設定封鎖了儲存），勾選框會停用。呼叫照常記錄，只是不會跨頁保留。

## 重新整理後會恢復什麼

下一次載入頁面時，保存的呼叫會接在新頁面自己的呼叫（與它的 [SSR](./ssr.zh-TW.md) 呼叫）之後。同一筆呼叫不會出現兩次。清單一樣最多 300 筆，超過時先移除最舊的。

來自前一個頁面的呼叫會標示出來：

- 那一列有「前一頁」標籤。
- 詳情寫著「來自前一個頁面」。
- [複製的報告](./error-reports.zh-TW.md)裡，請求那行結尾是 `(Client · from a previous page)` 或 `(SSR · from a previous page)`。
- 錯誤報告中，換頁前與換頁後的同一個錯誤會分開列出，不會合併。

之後再換頁，標示也會保留，所以兩頁前的呼叫仍有標示。

## 還沒完成的呼叫：結果未知

離開頁面時還在等待或串流中的呼叫，恢復後狀態是「結果未知」（指示符號為 `?`）。它的結果無從得知：觸發換頁的 `POST` 在伺服器上很可能已成功，但頁面沒收到回應。

- 保留它的 input、各次嘗試，以及離開前收到的串流事件。沒有耗時。
- 不算錯誤：不計入「錯誤」篩選、dock 徽章與錯誤報告。
- 複製的報告標題是 `❔ Outcome unknown (page left before the call finished)`。

## 大小上限

`sessionStorage` 很小（Chromium 每個網站約 500 萬字元），還要和 app 共用，所以保存的副本有上限：

- 資料超過 64 KB 的呼叫，保存時不含 input、output、串流事件與錯誤資料。其他欄位都保留，包括串流的事件數。詳情與報告在原位置顯示 `(not preserved: 120 KB, over the 64 KB limit)`（面板中文介面顯示「（未保存：120 KB，超過 64 KB 上限）」）。
- 整份副本不超過 1,000,000 字元。保留最新的呼叫，放不下的較舊呼叫不保存。
- 有東西沒保存時，工具列顯示「部分未保存」。提示寫出有幾筆呼叫未保存、幾筆未保存內容。重新整理後仍會顯示，直到清除。
- 瀏覽器拒絕寫入時（app 自己的資料已占滿儲存空間），工具列顯示「未保存：儲存空間已滿」，並刪除先前的副本，重新整理時不會顯示過時的清單。

## 清除

「清除」也會刪除保存的副本。清除的呼叫在重新整理或換頁後都不會回來。

## 上一頁與下一頁

瀏覽器從往返快取（back/forward cache）恢復頁面時，頁面還保有自己的清單，所以不會再恢復保存的呼叫。若你在後面的頁面清除過，恢復的頁面清單也會清空。若你在後面的頁面關閉了保留紀錄，恢復的頁面就不再保存。

這樣恢復的頁面在下一次清單有變化時，會保存自己的清單，取代你剛離開的那個頁面保存的呼叫。

## 同一個 origin 上的多個 app

保存的副本以分頁與 origin 為單位。同一個 origin 上的兩個 app 在同一個分頁先後開啟時會共用副本，第二個 app 會把第一個的呼叫當成來自前一個頁面。

## Production build

透過 [`production` 選項](./production.zh-TW.md)包含 inspector 的 build 也有同樣的勾選框，預設關閉。它的 headers 在記錄時就已遮罩；內容照原樣保存，和 dev server 相同。

## 保存了什麼、誰讀得到

保留紀錄開啟時，呼叫會寫入 app origin 上這個分頁的 `sessionStorage`，使用兩個 key：`orpc-inspector:preserve-log:enabled` 與 `orpc-inspector:preserve-log:records`。

- **Headers 會遮罩。** 請求與回應 headers、每次重試的 headers，以及錯誤資料中的 headers，名稱符合預設樣式的都存成 `***`。預設樣式符合 `password`、`passwd`、`secret`、`token`、`cookie`、`credential`、`api_key`／`api-key`／`apikey`、`authorization`、`proxy-authorization` 與 session id。報告範本裡設定的樣式不適用，因為不論面板有沒有開啟，頁面都會寫入副本。恢復的 `***` 無法顯示原始值。
- **內容不遮罩。** Input、output、串流事件與錯誤資料照原樣保存。登入回應的 `accessToken`，或回應中的個人資料，會以明文存在 `sessionStorage`。
- **誰讀得到：** 在那個 origin 上執行的任何 script、能存取該頁面的瀏覽器擴充功能，以及在那台電腦上使用 DevTools 的人。
- **保留多久：** 直到關閉保留紀錄、清除清單或關閉分頁。
- **立刻刪除：** 關閉保留紀錄或按「清除」。也可以在 DevTools → Application → Session storage 刪除這兩個 key。

只在重現 bug 時開啟，尤其是在共用的電腦上，或使用真實使用者資料時。
